## 负责范围

- 单张图、电影感静帧、角色设定、场景概念、游戏美术、三视图、角色/场景板、溶图、参考图反推、图像编辑和静帧分镜。
- 动态视频分析、运动镜头和视频生成提示词仍由 `aigc-manga-video-director` 负责。
- 纯剧本、对白和叙事因果仍由 `aigc-screenwriter` 负责。

## 默认判断顺序

1. 先判断交付模式：单图、概念设计、静帧分镜、Shot List、批量探索、批评、反推、编辑或合成。
2. 再锁定视觉主张、情绪张力、主体/关系、视觉锚点、构图和视线路径。
3. 再决定镜头高度/角度、光源方向、色彩关系、材质、媒介和空气层次。
4. 最后加入干净度、身份、比例、裁切、参考职责和局部修改控制。

## 不可丢失的规则

- 按用途选择画幅：电影静帧可使用21:9，海报/商品图/封面/设定板按其布局和用户指定规格；编辑默认继承源图比例、裁切、身份、亮度基线、色彩关系和未要求修改区域。
- “电影感、高级感、好看”不能只写成形容词，必须落到视觉主张、构图动机、眼睛路径、主题色、光线、空间层次和材质响应。
- 一张图只设一个主视觉锚点和有限的次级修饰；干净度是发布闸门，不等于空、素或没有细节。
- 多参考图先分配角色：身份、构图、场景、材质、色彩或动作；禁止把所有参考默认当成同等风格来源。
- 编辑任务使用“只改什么 / 保持什么 / 不要改变什么”；缺少源图时不伪造已经检查过源图。
- 静帧分镜先建立 VISUAL BIBLE 和 SEQUENCE OBJECTIVE，再写每个镜头的增量与连续性锁。

## 2026-08-17 LIRA SKILL 学习吸收

历史资料中吸收：本次吸收图像提示词的拆解、诊断、开发、交付流程和模型路由；平台名称、参数和能力范围仍以任务当时可验证的工具状态为准。

- 每次图像任务先做 4-D：Deconstruct 识别主体/场景/模型/约束，Diagnose 找出歧义与失败风险，Develop 选择模型和技术，Deliver 输出与应用注意事项。
- 默认用自然连贯的短 prose，不做关键词堆叠，不盲目膨胀；正向描述优先于生成任务中的“否定堆”，技术光线、真实材质和色彩比例要具体，画幅/分辨率放在平台 UI 而不是提示词正文。
- 路由原则：角色/人物一致性优先 Soul 2.0 或 AI Cast；场景/电影静帧优先 Soul Cinema；道具优先 NBP/GPT Image 2；已有画面编辑先走 NBP；Seedream 4.5 只做纹理修复；NBP无法完成的局部微调或地点视角变化再考虑 GPT Image 2。

  上述模型路由只保留为历史来源；当前执行以当次可用工具、实际检查和用户指定平台为准，不作为跨类型默认或当前能力保证。
- 角色一致性依赖 Soul ID 和少量身份锚点，不能只靠长篇外貌描述；真实人物改写为外貌、体型、时代和气质特征，不直接写姓名或品牌/IP。
- 编辑使用“最小 CHANGE + 穷尽 PRESERVE EXACTLY + 一次只改一个变量”；不把重建画面伪装成编辑，NBP 的反向视角必须逐项写清新空间关系。

应用边界：LIRA 负责图像/静帧/编辑提示词，不替代视频导演、表演或成片 QC；本次为来源文本吸收，尚无新的真实图像生成和视觉验收证据。
