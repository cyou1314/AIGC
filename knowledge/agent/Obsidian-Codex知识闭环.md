# Obsidian × Codex 知识闭环

> 用最少记录保留可复用经验；项目事实与跨项目知识分开。

## 默认快流程

1. **开始**：读取当前项目页，确认目标、权威输入、约束和唯一下一步。
2. **执行**：只打开会影响当前决定的知识页。
3. **产生结果**：登记真实文件、版本和状态。
4. **结束**：更新项目快照；记录一条经验候选或失败原因；未解决事项进入 [[TODO]]。

## 知识流向

`实际工作 → 项目页知识候选 → 第二个案例验证 → learning/经验 → agent/稳定流程或 Skill`

- 单一项目事实留在项目页。
- 能解释适用条件、失败边界并有证据的内容才进入 `learning/`。
- 重复执行、步骤稳定且能验收的内容才进入 `agent/` 或 Skill。
- 过期、重复、无证据内容降级或归档。

## 记录格式

`结论｜适用条件｜操作步骤｜反例/风险｜证据位置｜最近验证日期`

## 证据边界

- 文本和提示词是设计证据。
- 实际生成文件是结果存在证据。
- 检查记录是质量证据。
- 用户确认或真实交付是完成证据。

这些证据不能互相替代。

## 周日深度复盘

每周日按 [[周日深度复盘]] 处理近七天内容：合并重复经验、补证据、删除失效链接、更新职业能力和关系图谱。旧电脑项目历史不批量导回当前 vault。
