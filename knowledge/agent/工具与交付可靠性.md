# 工具与交付可靠性

> 安装、构建或配置成功，只能证明当前层完成；不能代替下一层验证。

## 五层状态

1. **已配置**：路径、账号或参数已经写入。
2. **已加载**：目标应用或新会话实际识别组件。
3. **功能通过**：用真实最小任务完成一次端到端调用。
4. **交付可用**：产物已经下载或打开，版本、架构和内容符合目标。
5. **清理完成**：本地进程、配置、残留文件和账号侧资源按范围核实。

## 执行顺序

- 每层记录证据、失败点和唯一下一步。
- 失败时停在当前层，不把上游成功写成整体完成。
- 会话加载问题优先重启应用并在新会话验证。
- CI 构建通过但上传失败时保留构建结论，将交付状态标为阻塞；先查配额和产物，再决定重跑或换分发方式。
- 卸载涉及远端资源时，本地清理和账号侧清理分开确认；不可恢复删除前核实具体资源。

## 适用边界

适用于 Codex 插件、Skill、MCP、桌面工具、CI artifact、网页桥接器和类似工具链。创作内容的质量仍按对应项目和成片 QC 判断。
