# 知识晋级与淘汰规则

本规则默认只在每周日 12:00 深度复盘或其他明确触发条件下执行。日常项目开始、进行和收尾不运行全库晋级审计。

## 证据优先级

1. 用户针对具体产出的明确接受、否决或修正；
2. 实际生成结果和成片验收；
3. 多轮修改或多个项目中重复出现的结果；
4. 最终分镜、提示词或工作流；
5. 未经本项目验证的外部经验和模型传闻。

最终提示词不是证明其中每句话都有效的充分证据。

## 知识层级

### 项目事实

只对当前角色、场景、剧情、素材或模型设置有效。保留在项目页，不进入通用知识。

### 候选经验

已经解决一次真实问题，但证据仍不足。写入项目页“知识反馈候选”，状态为 `待验证`。

### 已验证知识

满足以下任一条件：

- 在至少两个项目中得到相同方向的结果；
- 同一项目经过多轮真实生成和验收稳定成立；
- 用户明确确认它应成为长期默认；
- 它修复了现有知识中的明确错误，并有可复查证据。

根据归属更新：

- 职业能力 → `learning/`
- 项目生产流程 → `agent/`
- 人员稳定偏好 → `people/`
- 专业岗位标准 → 对应 `learning/` 能力页

### 过时或有害知识

优先缩小适用范围、改写或合并。只有继续保留会误导后续项目时才废弃，并保留简短原因。

## 每条经验的处理动作

- `保留项目专用`
- `候选验证`
- `强化`
- `改写`
- `合并`
- `降级观察`
- `废弃`

不允许使用“先全部加进去以后再说”。

## 更新原专业知识库时

1. 先确认对应岗位和唯一权威页面；
2. 不复制其他岗位全文；
3. 若改变交付字段，同步对应模板；
4. 若新增、移动文件或岗位关系改变，同步 `知识库索引.md`；
5. 模型、接口和工具规则写明适用范围及核验日期；
6. 项目专用标准不能自动升级为全项目默认。

## 停止条件

以下情况不升级：

- 没有实际生成或验收证据；
- 只在一个特殊镜头中有效；
- 与当前素材冲突；
- 需要猜测原因；
- 只是表达方式变化，没有改善结果；
- 会增加明显工作量但没有提高质量或减少返工。
