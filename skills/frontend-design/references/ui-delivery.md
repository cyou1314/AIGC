# UI网页设计合同

## 先选择交付

已有仓库：服从AGENTS、技术栈和现有设计系统。新局部页面：选满足目标的最小实现，不默认装大型框架。Figma编辑、可运行网页、概念截图和公开部署各自验收，不能互相替代。

## 页面与组件

确认核心路径和信息优先级再画界面。例如作品集应先帮助访客理解作品与服务，不用虚构数据填满SaaS仪表盘。形成简短token表：背景/文字/强调/状态色、字体角色、间距、边界/圆角。用户已提供系统时继承它。

中文标题不套英文长字距；检查全角标点和中英数字混排、字重回退、按钮扩宽与长文案折行。内容变化后重新检查，不把设计稿固定宽度当实际浏览器证据。

状态按需求实现，不强制每个静态作品集拥有登录/加载系统。表单有标签和错误说明；菜单可键盘访问；异步行为有加载、失败和成功反馈；没有后端的提交必须明确是演示，不能弹“已发送”假装真实处理。

## 真实验证

- 至少检查一个宽屏和一个窄屏，包含长中文、空数据或错误状态（适用时）。检查横向溢出、内容遮挡、固定栏遮挡和触控目标。
- 运行核心操作并检查实际结果：保存是否持久、跳转目标是否存在、筛选是否改变内容、失败是否可恢复。测试结束不留用户数据到公网上。
- Tab顺序、可见焦点、语义标签、文字/控件对比和reduced-motion属于功能验收。没有完整辅助技术测试时不宣称全面无障碍认证。
- 截图用于视觉对照，自动检测用于布局/状态证据，二者都需要明确范围。演示通过不代表真实支付、登录或生产后端通过。

交付说明包含运行方式、源文件、依赖、已验动作、尚未验证部分；发布仅在用户授权并读回真实发布结果后声明。
