# 专项审稿与学习

## 按交付选择标准

| 交付 | 先检查 | 专项问题 |
|---|---|---|
| 海报 | 权威文字、主体、用途尺寸 | 第一读/第二读、网格/留白、中文断行、Logo保护、缩略图可读、源文件与导出 |
| 人物 | 已确认身份、姿态、比例与面部 | 轮廓、识别锚点、表情/手部、面部到全身一致、多视图对齐；不要强制写实 |
| 服饰 | 时代/职业/用途和已锁身份 | 内外层、开合/绑带、接缝、活动空间、材质/重力、左右和背面一致；概念图不是裁剪纸样 |
| 场景 | 功能、比例、空间锚点 | 通路、门窗/支撑、透视、尺度参照、光源、叙事痕迹和视角连续；美图不等于建模或关卡交付 |
| UI网页 | 核心任务和实际状态 | 信息架构、token/组件一致、响应式、中文可读、键盘/焦点、空/错/加载反馈、真实交互 |

## 优先级与证据

blocker：错人/错商品、关键文字错误、无法完成核心任务、缺必需交付。
major：关键阅读或使用严重受损、设定矛盾、明显裁切/布局破坏。
minor：局部对齐、次级色彩或表面细节。taste：没有违反brief的风格偏好，不当作硬性失败。

证据层级：brief（仅输入）、source（源文件）、render（实际图像）、interaction（实际动作结果）。只声明实际做过的层级。设计者自己的“感觉不错”不能代替用户确认。

## 学习记录模板

```text
案例/用途：
权威brief与保持项：
基线/修改版文件和版本：
本轮唯一变量：
实际检查及观察：
最高影响问题/修改理由：
已知耗时/次数/费用：未知则写未知
结果：候选 / 已验证 / 拒绝
适用条件与反例：
下一次如何复验：
```

例：海报A/B只改标题层级，不同时换字体、主图和配色；服饰只改外层开合，锁住脸和内层；网页只改主行动位置，保持内容与功能。审美好坏不要归因于无法控制的随机生成。
