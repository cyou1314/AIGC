# JianYing 工作流

## 1. 只读检查

适用于第一次接触项目、用户只要求查看状态，或准备批量修改前。

```bash
scripts/inspect-draft.sh /absolute/path/to/draft
```

重点确认：剪映版本、草稿是否可读、视频/音频/文字轨道、素材路径、
字幕数量、时间线是否存在分歧，以及当前草稿是否正在被编辑器占用。

## 2. 单点修复

先用 `capcut texts`、`capcut segments` 或 `capcut segment` 找到精确对象，
再只改一个明确目标。例如：错别字、某一段字幕时间、某个片段音量。

单点修复完成后运行 `capcut lint <draft> -H`，并报告修改前后对象和备份状态。

## 3. 批量字幕或时间线修改

当修改超过一个对象时，使用 `capcut batch` 或项目内的参数化脚本。脚本
必须把输入、目标草稿、变更计划和验证步骤作为参数，不要把用户项目路径
和 segment ID 写死在 Skill 中。

批量写入应满足：

- 先 dry-run 或生成计划；
- 一次事务完成，失败时不留下半成品；
- 失败后不使用 `--continue-on-error`，除非用户明确接受部分写入；
- 写入后再次检查轨道、字幕和时间线。

## 4. 长视频改短视频

先确定平台、目标时长、保留的完整观点和禁止删除的内容，再执行剪辑。
优先使用场景切分、静音检测和重录检测提出候选范围；涉及语义取舍时，
让用户确认候选段落后再写入新草稿。

输出应是新的草稿目录或用户明确指定的副本，不能默认改动长视频原草稿。

## 5. 字幕生成或导入

如果已有 SRT/VTT/ASS，先检查时间基准、语言和帧率，再导入到副本中。
如果需要 Whisper，先运行 `capcut doctor -H` 确认可用的转写引擎，并标明
字幕是机器初稿还是人工确认稿。机器转写不能自动视为最终字幕。

## 6. 与其他 Skill 配合

- `auto-edit-video` 负责原始口播素材的语义粗剪和候选高光；本 Skill 负责
  将获批结果落到剪映草稿。
- `ffmpeg` 只负责确定性的裁剪、转码、抽帧、代理和音频处理；原始媒体
  必须保留，派生文件要经过媒体信息验证。
- `aigc-output-qc` 负责成片判断。本 Skill 只负责时间线结构和编辑结果。
