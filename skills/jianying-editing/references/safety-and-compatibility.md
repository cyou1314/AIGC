# 安全与兼容性

## 写入前

- 关闭剪映，再进行任何写操作。
- 第一次使用或剪映升级后，复制一个小型测试草稿。
- 先运行 `capcut doctor -H` 和 `capcut version <draft> -H`。
- 不要读取、记录或提交账号、令牌、私有素材或剪映缓存中的敏感信息。

## 写入时

- 优先使用 CLI 的事务、冲突检查、`.bak` 和历史快照机制。
- 不使用 `--force-write` 绕过编辑器占用、磁盘变化或版本边界，除非用户
  明确授权并知道可能覆盖什么。
- 不直接修改原始媒体；媒体替换和路径修复要单独说明。
- 复杂变更先用 `--dry-run`、`lint` 或只读 diff 验证，再实际写入。

## 写入后

- 检查草稿是否仍能被 CLI 读取，轨道和字幕数量是否符合预期。
- 关闭 CLI 操作后重新打开剪映，只检查本次变更涉及的区间。
- 如果剪映提示“路径异常”“素材不可用”或草稿无法打开，停止后续写入，
  先用版本信息、素材注册和路径诊断定位问题。

## 版本边界

剪映草稿结构会随版本变化。以当前安装的 `capcut describe`、`capcut version`
和真实剪映生成的测试草稿为准，不把旧版模板或第三方教程中的 JSON 字段
当作稳定接口。
