# 完整专业生产工作流

## 一、工作方式

这不是所有任务强制走满的九步流水线，而是“共同生产底座 + 分类型专业分支 + 可复用R0–R8模块”。任务大小决定文档深度；真实风险决定验收力度。只要脚本就结束于脚本，只要图片就不强制扩展成影片。

每轮先建立五项合同：目标交付、权威输入、不可变约束、成本/时长/规格、验收方式。已有项目先读项目页、最新实际文件和本轮变更；不要依靠聊天猜版本。

当前动作只选一个主Skill；需要跨阶段时记录交接文件、来源与下一步。专家Skill的明确调用优先于通用路由。

## 二、R0–R8：保留完整原流程的专业模块

| 模块 | 输入与动作 | 必须留下的产物 | 通过条件 |
|---|---|---|---|
| R0 项目治理 | 读项目页、版本、预算、权威资料；判断生产类型 | 项目快照、当前阶段、唯一下一步 | 输入权威和本轮边界清楚；缺少输入明确列出 |
| R1 编剧 | 整理故事、目标、冲突、信息顺序、因果与节奏 | 故事结构/剧本版本/证据链 | 行为有动机，信息有来源，结局有铺垫；用户确认本轮剧本 |
| R2 导演与分镜 | 视频分析、节拍、镜头、空间、表演、时长 | 镜头表、动作因果、时间合同、分镜/预演 | 镜头承担叙事功能；空间连续；动作不是平均拆成机械节拍 |
| R3 静帧与资产 | 角色/场景/道具Bible、首尾帧、参考职责 | 资产ID、选用图、变体与镜头映射 | 身份、服饰、比例、位置、指定文字一致 |
| R4 音频 | 转录、情绪/节奏分析；需要时配音/配乐/音效 | 对齐文本、声音计划、实际音频或视觉提示词 | 真实词句/时长；配音生成与转录分开；音乐来源可说明 |
| R5 提示词与生成 | 从确认分镜转换，按工具能力适配，局部返修 | 工具专用提示词版本、任务记录、生成回执 | 无相互矛盾约束；任务已完成并取得实际结果才登记生成 |
| R6 输出核验 | 对比实际素材与剧本/分镜/提示词；分类返修 | 带时间点/区域的QC、局部修复决策、采用文件 | 按本类型检查，严重缺陷关闭；未请求QC不编造通过 |
| R7 知识治理 | 收尾、交付、项目页/Drive/Obsidian归档 | 实际交付清单、待跟进、经验候选 | 交付可打开；状态如实；不把个案直接提升为全局规则 |
| R8 Skill演进 | 比较重复问题、测试与成功证据 | Skill补丁、变更说明、回归结果、版本 | 改动有适用范围和证据，可回滚；不以“多装Skill”代替能力补齐 |

R0/R7贯穿所有类型；R1/R2在叙事项目使用更深；图像、3D、音频、文档等使用各自验收，不套短剧标准。R8属于维护活动，不是每个创作任务的强制成本。

## 三、九类生产分支

### 1. 叙事影像：漫剧、短剧、动画、MV、儿歌

输入：权威故事/剧本、时长、比例、角色与场景、真实歌曲/歌词（涉及音乐时）。

顺序：故事诊断 → 剧本锁定 → 时长与分镜 → 角色场景Bible → 首尾帧/关键动作 → 工具专用生成 → 镜头选择/剪辑 → 连续性与声音QC → 导出。

关键检查：动机—行为—后果闭环；镜头有目标；入出画、轴线、视线和武器身份一致；动作有发力/接触/反作用；音频位置与实际影像相符。MV先按真实音乐节拍分段，儿歌按歌词和年龄适宜表达，不按商业短剧开头强制结构。

交付：用户要求的剧本/分镜/提示词，或实际影像加可恢复工程。比率、无BGM等是项目约束，不是所有项目默认值。

### 2. 图像设计：角色、概念、海报、商品图、静帧

输入：用途、尺寸/比例、主视觉、精确文字、品牌资产及各参考图的职责。

顺序：设计brief → 构图/版式 → 单张验证 → 局部修改/变体 → 按用途导出。商品身份、包装标签和指定文字须逐项核验；需要精确排字时采用可编辑排版，不依赖生图猜字。

关键检查：主体可辨、商品真实、裁切安全区、文字正确、系列一致、透明背景与印刷/屏幕用途匹配。交付实际PNG/JPG或要求的设计源文件；图像提示词不是图片。

### 3. 商业内容：广告、UGC、商品演示、社媒

输入：受众、商品事实、利益点、CTA、渠道、素材权利与禁止主张。

顺序：事实/卖点表 → 创意brief → 脚本/镜头 → 产品证据与真实演示 → 一条样片 → 变体 → 渠道验收。仅在要求UGC时选择开箱、试穿、教程、网站体验等对应子类型。

关键检查：不捏造功能、折扣、用户评价或测试结论；演示步骤有效；品牌与价格文字准确；CTA明确但不强制每个广告采用同一结构。效果评估需要真实发布指标，不把“有钩子”当转化证据。

### 4. 主持解说：数字人、口播、无脸知识视频

输入：有来源的讲稿、主持身份/授权、语言、声音、时长、辅助画面。

顺序：事实核验 → 朗读与时长测试 → 身份/声音锁定 → 辅助镜头 → 合成 → 字幕与音画对齐 → 导出。无脸视频选明确无脸路线；已有实拍口播只要求剪辑时转后期分支。

关键检查：事实、发音、语速、口型、字幕、画面与话语是否一致。交付实际视频；仅需要讲稿时不创建主持人、不调用付费生成。

### 5. 后期制作：口播粗剪、剪映工程、字幕、版本导出

输入：原媒体/现有工程、素材路径、保留/删除要求、字幕规范、导出规格。

顺序：只读检查 → 副本与素材索引 → 逐切点决策 → 小批编辑 → 工程重开 → 试听目视 → 导出核验。原始口播保守粗剪可用auto-edit-video；已有剪映工程用jianying-editing；单纯转换用ffmpeg。

关键检查：不能断句断因果，字幕与声画对齐；不误删呼吸/反应；音量无异常；工程可重链接。验收按要求是可编辑工程还是成片，不默认用导出视频替代工程。

### 6. 音频：配音、播客、音乐、音效

输入：文本/音频、授权、语言、情绪、时长、用途、采样率/声道/分轨需求。

顺序：文本/结构锁定 → 声音方向或音乐brief → 短样试听 → 生成/录制 → 剪辑与混音 → 实测时长/峰值/试听 → 文件与分轨交付。

关键检查：逐字正确、发音与情绪、噪声/破音/失真、切口和用途响度。响度指标以具体平台合同为准，不统一硬套数值。转录Skill不生成音乐，audio-to-prompt只负责将声音转为视觉提示。

### 7. 3D：模型、材质、骨骼、动画、预演、打印

输入：目标软件/引擎、用途、单位、轴向、格式、面数/拓扑/UV/骨骼合同。

顺序：资产brief → 参考/模型 → 目标软件导入 → 材质/绑定/动画测试 → 优化 → 包装交付。Blender预演与Meshy生成分别核验；实体打印另检查尺寸、封闭性、支撑和材料要求。

关键检查：真实模型可导入、比例/轴向正确、材质不丢失、动画有效。预览图不是可用GLB证明；模型生成成功不是打印成功。

### 8. 知识：研究、文档、PPT、表格、课程

输入：主题、受众、权威资料、结构完整性要求、目标格式。

顺序：资料/版本核对 → 来源证据 → 结论与结构 → 可编辑制作 → 渲染/公式计算 → 内容和版面核验 → 导出交付。

关键检查：事实有来源、引用支持对应论断、结构未丢失、图表不造数据、公式算得出。长文或用户已有结构不得因为套模板被擅自缩减。

### 9. 数字产品：网站、应用、Agent、交互内容

输入：用户路径、已有仓库/技术栈、运行环境、功能与权限边界。

顺序：检查代码 → 确定最小完整用户路径 → 实现 → 本地运行与异常测试 → 安全配置 → 用户要求时部署 → 实际访问核验。

关键检查：核心操作真实可用、错误有处理、配置不泄密、维护路径清楚。已有仓库服从当前技术栈；构建成功不等于上线成功，网站模板也不是所有游戏引擎支持。

## 四、质量与成本控制

先验证最高风险、最贵的一个节点，再批量扩展：一张角色关键帧、一段动作、一条配音、一套模型导入。没有已确认方向前不要批量烧点数。

| 决策 | 收益 | 成本/风险 | 适用场景 |
|---|---|---|---|
| 最小闭环 | 快速发现工具/方向问题 | 样本不能代表复杂全片 | 新设备、新工具、预算紧 |
| 标准完整生产 | 资产和交接可追溯，适合返修 | 前期文档与版本成本 | 常规交付、系列作品 |
| 深度预演与锁定 | 空间/动作/资产更稳定 | 建模、预演、锁版本更耗时 | 复杂打戏、长叙事、多人协作 |

质量问题分级：阻断交付（身份错、文件打不开、事实错误）先修；显著影响体验（节奏、连续性、发音）随后修；风格偏好留用户选择。每次返修明确保留/允许改变/修改区域，优先局部修复；根因是剧本就返回剧本，不靠增加提示词掩盖。

## 五、停点与交接

阶段状态区分：输入不足、方案完成、运行时阻塞、实际结果取得、已采用、已交付、用户确认。生成回执只登记非空真实文件；文件存在检查不替代创作品质验收。

每轮结尾交付“本轮实际产物 + 验证证据 + 未解决问题 + 唯一下一步”。按[项目合同](PROJECTS.md)存储，不将密钥、聊天全文或真实账号数据写入通用知识。
