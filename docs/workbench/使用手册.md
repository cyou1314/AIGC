# Xan：分类与使用手册

版本1.3.2 · 2026-10-20 · 基于已整理的20个本地Skill及公司扩展。

## 从这里开始

你不用记住技能英文名。直接说要交付的结果，工作台选择一个主模块。专业模块按需要交接，检查不等于改写，提示词不等于实际生成。

最常用的五句话：

1. “把这个设定写成完整剧本。”
2. “把这段确认剧情写成30秒Seedance 2.5完整版提示词，台词不改。”
3. “检查这两条提示词的站位和口型，只报告问题。”
4. “从附件按集原样提取台词，不翻译、不润色、不去重。”
5. “依据剧情和参考人物写3:4海外短剧海报提示词。”

## 两种安装方式，三个能力层

A. 技能插件版：八个可发现的入口＋按需参考＋小型确定性辅助。安装到支持的ChatGPT/Codex宿主后按实际可用工具工作。插件不自带MCP服务、支付、Seedance或飞书连接，不等于本地剪映。

B. 已有GPT兼容版：把GPT_主指令.txt粘到Instructions，解压知识文件后逐个上传到Knowledge，不把ZIP当已安装技能。规则要点在指令，细节放知识；新建/编辑资格看当前账户和工作区。

能力层：
1. 文本方法可直接用：剧本、提示词、审查方向、配乐方案、剪辑计划。
2. 文件运算有条件：代码执行环境和依赖可用时处理XLSX、运行随包账本与台词脚本；先验证工具，不假定。
3. 本地/外部执行另接：FFmpeg、转录API、视频/音乐生成、Figma/文档服务等，需要真实运行时、连接、资产与授权。

Codex完整源快照另附，保留原20个Skill和安装/验证工具，不是GPT知识文件。内部兼容或复现可用；源快照不包含本人的登录或项目媒体，也不代表新机器已经安装。

## 常用生产路线

短剧：新剧情→编剧；确认稿→导演；需要角色图→图像；有音频→声音；需要执行→当前实际生成工具；成片→后期与有证据QC。只要提示词，到提示词即止。

海报：剧情/精确剧名→图像主视觉与标题关系；需要精确成品→生成主视觉＋可编辑置字；按实际图检查。海报默认3:4只限海外短剧分支，其他任务按用途。

声音：原文提取与原音转录分别处理；配乐先动态再配器；音乐停不等于对白/拟音也停；未试听不编高潮点。

返修：先分清文本冲突、工具能力、生成执行与后期缺陷，保护已接受部分，改失败层。没有新实片只说规则与设计自查，不说生成成功。

## 提升效率的工作习惯

- 一次给目标、已有材料、范围和保留项即可，其他能推断的让工作台处理。
- 对摄影开放就说“机位和切点你决定”；有锁就明确“总长24秒”“这一组动作真实不切”“只改第2板”。
- 给完整旧提示词，避免仅凭截图里几个字段猜动作/对白。
- 需要原样提取就说原样，不让标点清理变成润色。
- 跨聊天带快照，不要求模型凭记忆找最新稿。
- 批量前先确认代表方向；局部失败不要重做全套。

## 版本与验证

导入同版本主指令和18份分层知识，不混新旧。平台能力变化与公司规则更新要另验，不按“新”就机械覆盖电影原理。随包测试清单用于Preview验收，结构/脚本通过不等于GPT行为、画面或听感通过。

完整源20个Skill另保留它们的源版本与许可证。此工作台是整理后的八入口适配，不把原Skill源码迁移、知识检索、插件注册和实际执行混为同一件事。


## 1.3.0完整性补强

八入口保留简洁使用方式；每个模块现在直接附其原Skill全部文件，不再只放ZIP或摘要。source-map给到具体入口/参考/脚本路径，source-integrity.json逐文件SHA256记录。共享通用知识与模板也直接随包，个人vault不再是普通任务的必需条件。

GPT兼容包新增八份完整专业资料与恢复的音乐候选表，共18份知识文件；原文件中的历史路径/平台规则按执行合同解释。原20技能源码和原公司技能包另保留以便溯源。音乐候选表来自本对话已读取内容的整理，不是已试听或全部曲名/版本均核实的清单；旧音乐附件当前无法重新取回，不声称保有其字节原件。

工作流自足指方法与随包本地工具完整、缺依赖时有继续路径。外部服务、编辑器和模型效果仍受实际连接与输入约束；任何“不卡”都不能靠假造产物/省掉必须内容实现。请先读最简单使用方式.md，需要执行时按执行合同.md预检。

用户已排除剪映/CapCut CLI：不检查、不安装、不调用。后期按手动剪映交接执行；来源中的CLI步骤只作历史参考，素材保护和验收方法继续保留。
