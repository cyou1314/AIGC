# 安装与验证

整理版本：1.3.5；平台说明核对日期：2026-10-20。

## 先选择路径

优先使用技能插件包：Xan，八个分类入口，由宿主按任务选用。插件不含服务端或账户凭证；创建为私有只保存这套技能，不自动安装本地CLI、不公开、不调用生成。

已有自定义GPT需要沿用时，使用GPT兼容包。当前官方说明对个人新建GPT有限制，并建议迁移到插件；已有GPT可否编辑和管理工作区新建资格取决于账户/工作区权限。见[官方配置与可用性说明](https://help.openai.com/en/articles/8554397-creating-and-editing-gpts)。这里没有读取你的账户设置，不替你断言具体按钮一定存在。

## 技能插件包

1. 打开已创建的私有插件页面，检查名称、版本与八个技能。
2. 按当前界面的安装/启用入口使用；只保存到账号不等于当前聊天已经启用。
3. 新任务选择插件后先发一个提示词或只检查任务，按Preview_验收清单.md核对。
4. 要执行XLSX/FFmpeg/生成/在线服务时再检查能力；没有工具交方案，不假造完成。
5. 需要在别处导入时使用单根目录plugin.json格式的插件ZIP，不把GPT知识ZIP当插件。

## 已有GPT兼容包

1. 解压GPT兼容包，找到GPT_主指令.txt、GPT_配置清单.json和knowledge目录。
2. 在有编辑权限的GPT中填写名称/描述，粘贴主指令到Instructions。
3. 将knowledge内18份Markdown（00–08导航、10–17完整资料及音乐候选表）逐个上传到Knowledge；JSON清单是人工配置参考，不是支持一键导入的声明。
4. 按任务启用当前可用的代码执行/文件分析、搜索或图像能力。提示词/剧本任务不需要生成接口；上传知识不等于获得网络、剪映或Seedance执行权限。
5. 在Preview运行验收案例，再保存。不要以“上传成功”代替行为验证。
6. 如果不能编辑现有GPT，可把主指令与相关知识用于当前支持的项目/工作流界面；它不保证跨聊天永久保留。

## Codex原20技能完整源快照

附加ZIP是本私有仓库可移植源码快照，保留全部20个Skill、references、scripts、测试与各自许可证。不要覆盖CODEX_HOME或复制旧机器运行配置。

在目标电脑把源文件解压到普通工作目录，让Codex先读README.md和AGENTS.md，再运行当前解释器下的scripts/validate.py及scripts/manage.py install/upgrade。已安装同名技能先检测修改、备份并按原安装器处理；第三方CLI/API和媒体依赖单独配置。新机器不继承本机同步基线/凭证。

源快照与八入口插件是两种安装层级：前者用于保留原工具与开发能力，后者提供便于日常调用的组织方式。不需要把20＋8入口同时塞进一个GPT。

## 权限和材料边界

公司包只用于你的私有工作流。公开或团队传播前按各部分许可/公司要求处理；原许可证随源码保留。本包没有上传公司素材、聊天记录、密钥或私人项目页。GPT/插件的实际文件访问、网络和服务能力由宿主决定。


## 1.3.0完整性补强

八入口保留简洁使用方式；每个模块现在直接附其原Skill全部文件，不再只放ZIP或摘要。source-map给到具体入口/参考/脚本路径，source-integrity.json逐文件SHA256记录。共享通用知识与模板也直接随包，个人vault不再是普通任务的必需条件。

GPT兼容包新增八份完整专业资料与恢复的音乐候选表，共18份知识文件；原文件中的历史路径/平台规则按执行合同解释。原20技能源码和原公司技能包另保留以便溯源。音乐候选表来自本对话已读取内容的整理，不是已试听或全部曲名/版本均核实的清单；旧音乐附件当前无法重新取回，不声称保有其字节原件。

工作流自足指方法与随包本地工具完整、缺依赖时有继续路径。外部服务、编辑器和模型效果仍受实际连接与输入约束；任何“不卡”都不能靠假造产物/省掉必须内容实现。请先读最简单使用方式.md，需要执行时按执行合同.md预检。

后期不安装或调用剪映/CapCut CLI；直接使用手动剪映交接方案。来源中的CLI代码为历史参考，不是当前安装要求。

Xan图标原图随包保存在assets/deck-icon.png；已有GPT的手动配置可使用同名资源。
