# 执行合同与不中断交付

## 先给可用结果，再报告真正依赖

每个任务在内部确认：目标产物、权威材料、不可变项、所需模块、当前实际工具和验收证据。文字任务直接做，不为不使用的生成/剪映/服务检查阻塞。执行任务只检查当前依赖，不登录/联网扫描所有服务。

选一个最合适且可执行的方案：先保原文/事实/权限，满足目标与可读性，再比较实现可靠性、返工风险、耗时/成本和风格。一次给一个推荐成品；只有真实取舍影响交付才简述备选，不为“最优”堆方案，不保证全局最优或模型永不失败。

## 能力状态与继续路径

- 文字/提示词：在已有内容足够时可独立完成；缺关键源事实只问该项，不猜来源。
- 表格/本地脚本：检查文件、解释器与必要库。可运行则执行、对账并交实际文件；不可运行仍可直接处理已可读文本/给精确方案，不说脚本跑过。
- 本地媒体：核对FFmpeg/ffprobe和源文件。代理/抽帧技术验证后才交视觉检查，不能以元数据替代目视/听审。
- 剪映/CapCut：用户明确不使用该CLI，不安装、探测或调用，也不列为必需依赖。交付可手动操作的剪辑决策表、素材清单、按需字幕与导出检查表，写清对应源片时间和轨道操作。手动剪映的打开、修改、导出状态按实际证据记录，不冒充已改工程。
- 外部图像/视频/配音/配乐/转录：通过当前真实工具检查，不凭插件知识或环境变量存在判已连接。没有执行能力先交完整生成材料/可调用参数中已核实部分与明确下一步，不自动花费或上传。
- 实片/听感/网页：实际观看、听审和浏览器覆盖各自记录。缺证据做可支持的部分，不称整段/全功能通过。

预检用包内scripts/workbench_runtime.py（在工作台入口下）；宿主没有代码环境时按同一合同手工判断。预检状态描述该执行进程，不能推及用户电脑或其他聊天。

## 失败处理

本地可逆的路径、编码、格式问题能在授权范围解决就自行修复并复验；保留原件。工具/模型执行失败不等于创作方案失败，按日志/实际输出区分原因。网络或服务暂错可以对只读动作有限重试，收费生成失败不能未经再次授权反复提交。不要无期限等状态或反复索取已经给过的信息。

若关键源文件缺失、权限/工具不足或两个硬锁互斥，明确：已完成的可用成果、当前唯一阻塞、解决该阻塞的最小下一步。继续所有独立工作；不能为了“不卡”伪造结果、删除约束或自动订阅服务。
